# BAP Navigation_SD: коды манёвров и направлений

Справочник по `ManeuverDescriptor` из **BAP Function Catalogue — Navigation_SD LAH V2.80**, функция **23 / `0x17`**, раздел 13.

- LSG: `0x32` — Navigation_SD.
- CAN FSG → ASG в проекте: extended `0x17333211`.
- `Maneuver_1` — текущий манёвр, `Maneuver_2` и `Maneuver_3` — следующие.
- Точный смысл `Direction` зависит от `MainElement`: для обычного поворота это направление поворота, для круга — направление съезда, для разворота — сторона разворота.

## 1. Запись манёвра

Каждый `Maneuver_x` содержит:

```text
MainElement  Direction  Z_LevelGuidance  Sidestreets.length  Sidestreets[]
     1 byte    1 byte        1 byte            1 byte        0–16 bytes
```

Пример обычного поворота направо на 90° без боковых улиц и Z-level:

```text
0D C0 00 00
```

Пример поворота влево на 45° с одной дополнительной улицей вправо на 90°:

```text
0D 20 00 01 C0
```

`Sidestreets` — дополнительные направления **того же манёвра**, а не `Maneuver_2`.

## 2. Кодирование Direction

```text
angle_degrees = raw × 360 / 256
```

Шаг — 1,40625°, округлённо 1,4°. Направление задаётся относительно текущего движения и увеличивается против часовой стрелки: прямо → влево → назад → вправо → прямо.

| Raw | Угол | Смысл |
|---:|---:|---|
| `0x00` | 0° | прямо |
| `0x10` | 22,5° | пологий поворот влево |
| `0x20` | 45° | влево по диагонали |
| `0x30` | 67,5° | круто влево |
| `0x40` | 90° | влево |
| `0x60` | 135° | назад и влево |
| `0x80` | 180° | назад |
| `0xA0` | 225° | назад и вправо |
| `0xC0` | 270° | вправо |
| `0xE0` | 315° | вправо по диагонали |
| `0xF0` | 337,5° | пологий поворот вправо |

Промежуточные значения разрешены. В текущем HUD сектор изображения выбирается с округлением до ближайших 22,5°:

```c
sector = ((direction + 8) >> 4) & 15;
```

Для `LaneGuidance` значение `0xFF` дополнительно означает невалидное направление. В описании `ManeuverDescriptor.Direction` специального значения `0xFF` нет.

## 3. Основные манёвры

| Код | MainElement | Смысл | Отображение в текущем HUD |
|---|---|---|---|
| `0x00` | `NoSymbol` | символа нет | ничего |
| `0x01` | `NoInfo` | информации нет | ничего |
| `0x02` | `DirectionToDestination` | направление к цели | обычный поворот по `Direction` |
| `0x03` | `Arrived` | прибытие | `arrived[0]` |
| `0x04` | `NearDestination` | приближение к цели | обычный поворот по `Direction` |
| `0x05` | `ArrivedDestinationOffmap` | прибытие к цели вне карты | обычный поворот по `Direction` |
| `0x06` | `OffRoad` | вне дороги | обычный поворот по `Direction` |
| `0x07` | `OffMap` | вне карты | обычный поворот по `Direction` |
| `0x08` | `NoRoute` | маршрута нет | обычный поворот по `Direction` |
| `0x09` | `CalcRoute` | расчёт маршрута | `...` |
| `0x0A` | `RecalcRoute` | перерасчёт маршрута | `...` |
| `0x0B` | `FollowStreet` | следовать по дороге | `turn[0]`, обычно прямо |
| `0x0C` | `ChangeLane` | смена полосы | обычный поворот по `Direction` |
| `0x0D` | `Turn` | поворот | `turn[sector]` |
| `0x0E` | `TurnOnMainroad` | поворот с продолжением по главной дороге | обычный поворот по `Direction` |
| `0x0F` | `ExitRight` | съезд направо | `exit[1]` |
| `0x10` | `ExitLeft` | съезд налево | `exit[0]` |
| `0x11` | `ServiceRoadRight` | сервисная дорога направо | обычный поворот по `Direction` |
| `0x12` | `ServiceRoadLeft` | сервисная дорога налево | обычный поворот по `Direction` |
| `0x13` | `Fork-2` | развилка на две ветви | `exit[0/1]`; при `Direction = 0` вправо |
| `0x14` | `Fork-3` | развилка на три ветви | `exit[0/1]`; при `Direction = 0` влево |

Для съездов с эстакадой/рампой спецификация предписывает использовать `0x0F` и `0x10` совместно с `Z_LevelGuidance`.

## 4. Круги и площади

Суффикс `TrsRight` / `TrsLeft` означает **правостороннее / левостороннее движение**, а не направление съезда или поворота. Угол съезда задаётся отдельно полем `Direction`.

| Код | MainElement | Смысл | Отображение в текущем HUD |
|---|---|---|---|
| `0x15` | `RoundaboutTrsRight` | круг, правостороннее движение | `round[sector]` |
| `0x16` | `RoundaboutTrsLeft` | круг, левостороннее движение | `round[sector]` |
| `0x17` | `SquareTrsRight` | площадь/перекрёсток, правостороннее движение | обычный поворот по `Direction` |
| `0x18` | `SquareTrsLeft` | площадь/перекрёсток, левостороннее движение | обычный поворот по `Direction` |
| `0x1A` | `ExitRoundaboutTrsRight` | съезд с круга, правостороннее движение | обычный поворот по `Direction` |
| `0x1B` | `ExitRoundaboutTrsLeft` | съезд с круга, левостороннее движение | обычный поворот по `Direction` |
| `0x1D` | `PrepareRoundabout` | предварительное указание круга | обычный поворот по `Direction` |
| `0x1E` | `PrepareSquare` | предварительное указание площади/перекрёстка | обычный поворот по `Direction` |

Важно:

- `0x1A` — именно **съезд с круга**, а не просто круг направо.
- `0x15` и `0x16` в текущем HUD используют одну таблицу `round[]`; отдельной геометрии для левостороннего движения пока нет.
- `0x1A` и `0x1B` попадают в общий fallback `turn[]`, а не в `round[]`.
- `PrepareRoundabout` — предварительное сообщение, поэтому текущий HUD также использует обычную стрелку поворота.

Пример:

```text
15 40 00 00
```

Это круг с правосторонним движением и съездом влево на 90°, а не «круг направо».

## 5. Развороты и специальные повороты

| Код | MainElement | Смысл | Отображение в текущем HUD |
|---|---|---|---|
| `0x19` | `Uturn` | разворот | `uturn[0]` при `Direction <= 0x80`, иначе `uturn[1]` |
| `0x1F` | `PrepareUTurn` | предварительное указание разворота | обычный поворот по `Direction` |
| `0x22` | `MichigangTurn` | разворот по схеме Michigan; написание именно так в каталоге | обычный поворот по `Direction` |
| `0x23` | `DoubleTurn` | двойной поворот | обычный поворот по `Direction` |
| `0x29` | `MainRoadRight` | главная дорога направо | обычный поворот по `Direction` |
| `0x2A` | `MainRoadLeft` | главная дорога налево | обычный поворот по `Direction` |

Для `Uturn` тип `Direction = 0x80` обозначает назад/180°, но сам `MainElement = 0x19` сообщает HUD, что нужна специальная иконка разворота, а не обычный поворот.

## 6. Предварительные указания

| Код | MainElement | Смысл |
|---|---|---|
| `0x1C` | `PrepareTurn` | предварительный поворот |
| `0x1D` | `PrepareRoundabout` | предварительный круг |
| `0x1E` | `PrepareSquare` | предварительная площадь/перекрёсток |
| `0x1F` | `PrepareUTurn` | предварительный разворот |

`PrepareTurn` обрабатывается так же, как `Turn`: `turn[sector]`. Остальные `Prepare*` в текущем HUD используют общий fallback `turn[sector]`.

| Код | MainElement | Смысл |

| `0x26` | `DirectionToWaypoint` | направление к промежуточной точке |
| `0x27` | `ReducedGuidance` | упрощённое ведение по маршруту |
| `0x28` | `LeaveParking` | выезд с парковки |
| `0x2B` | `DirectionToEntrypoint` | направление к точке въезда |
| `0x2C` | `Take Ferry` | паромная переправа |
| `0x2D` | `Take CarTrain` | погрузка на автопоезд |
| `0x2E` | `UnderpassRight` | подземный проезд направо |
| `0x2F` | `UnderpassLeft` | подземный проезд налево |
| `0x30` | `OverpassRight` | надземный проезд направо |
| `0x31` | `OverpassLeft` | надземный проезд налево |
| `0x32` | `Toll Gate` | пункт оплаты проезда |
| `0x33` | `Toll Gate - ETC` | пункт оплаты с ETC |
| `0x34..0xFF` | reserved | зарезервировано |

Пометка `DF4.7` в каталоге относится к версии профиля/документа, а не к CAN ID.

Все типы, для которых в `nav_pick()` нет отдельной ветки, в текущем HUD рисуются обычной стрелкой `turn[sector]` по `Direction`.

## 8. Зарезервированные RampUp/RampDown

| Код | Обозначение в каталоге | Использование |
|---|---|---|
| `0x20` | `reserved - ExitRight-RampUp` | не использовать на этом интерфейсе |
| `0x21` | `reserved - ExitRight-RampDown` | не использовать на этом интерфейсе |
| `0x24` | `reserved - ExitLeft-RampUp` | не использовать на этом интерфейсе |
| `0x25` | `reserved - ExitLeft-RampDown` | не использовать на этом интерфейсе |

Эти значения зарезервированы для проектов, где Z-level не передаётся отдельным параметром. Вместо них нужно использовать `0x0F` / `0x10` и `Z_LevelGuidance`.

## 9. Z_LevelGuidance

| Код | Смысл |
|---|---|
| `0x00` | нет Z-LevelGuidance |
| `0x01` | вверх |
| `0x02` | вниз |
| `0x03..0xFE` | зарезервировано |
| `0xFF` | не поддерживается |

Z-level — это не угол поворота и не `Direction`: он описывает вертикальный уровень съезда или эстакады.

## 10. Как HUD показывает название улицы следующего манёвра

Для текста используется **TurnToInfo**, функция **20 / `0x14`**, а не `ManeuverDescriptor`:

> «the textual description of the street to turn to in the next maneuver».

Это название **целевой улицы ближайшего манёвра** — улицы, на которую предстоит повернуть. Обычно оно относится к `Maneuver_1`, то есть к манёвру, к которому автомобиль сейчас приближается.

Сообщение содержит две UTF-8 строки:

| Поле | Назначение | Максимум по спецификации |
|---|---|---:|
| `TurnToInfo` | улица, на которую предстоит повернуть | 75 байт + байт длины |
| `SignPost` | направление следования по указателю: «в направлении …» | 30 байт + байт длины |

Текущее отображение:

- строка располагается над основной стрелкой: `x = 2`, `y = 3`, ширина окна 138 px;
- используется шрифт `hud_font_mstreet` высотой 18 px;
- если текст помещается, он центрируется; если нет — включается циклическая бегущая строка со скоростью 35 px/s;
- типы улиц сокращаются: «улица» → «ул.», «проспект» → «пр-т», «переулок» → «пер.» и т. д.;
- при наличии `SignPost` он добавляется в ту же строку через `→`, например: `A10 → Hamburg`;
- пустые обновления игнорируются, поэтому предыдущее название не затирается промежуточными пустыми сообщениями;
- при `RG_Status != 1` название очищается; без нового `RG_Status` оно сохраняется до следующего непустого `TurnToInfo`;
- показ можно отключить настройкой `HUD_STREET_ON`.

Для отображения требуется непустой `TurnToInfo`. Сам по себе `SignPost` без названия улицы на экран не выводится.

### Название текущей улицы не показывается

Для текущего положения автомобиля BAP предусматривает отдельную функцию **CurrentPositionInfo — 19 / `0x13`**:

> «the textual description of the current vehicle position (e.g. street name …)».

Она может содержать текущую улицу, номер дома и дополнительное описание, до 96 байт + байт длины. **В текущем HUD функция `0x13` не разбирается и на экран не выводится.** Поэтому улица, на которой автомобиль находится в данный момент, на HUD не отображается.

Коротко:

```text
0x14 TurnToInfo          → показываем целевую улицу ближайшего манёвра
0x13 CurrentPositionInfo → не показываем текущую улицу
```

### У Maneuver_2 название улицы не выводится

`ManeuverDescriptor` содержит только `MainElement`, `Direction`, `Z_LevelGuidance` и `Sidestreets`; текстового названия целевой улицы для `Maneuver_2` в нём нет. Поэтому для следующего после ближайшего манёвра HUD показывает **только маленькую стрелку**, без названия улицы.

## 11. Краткая шпаргалка по текущему HUD

```text
00, 01          → ничего
03              → arrived
09, 0A          → ...
0B              → прямо
0D, 1C          → turn[sector]
0F, 10          → exit[1], exit[0]
13, 14          → exit[0/1]
15, 16          → round[sector]
19              → uturn[0/1]
все остальные   → turn[sector]
```

Реализация выбора изображения: `supermini_hud2/hud_mockup.c`, функция `nav_pick()`.
